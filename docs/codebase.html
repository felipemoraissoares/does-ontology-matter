Arquitetura, módulos e fluxo de dados — Does Ontology Matter? (ITA, 2026)

Visão Geral

O projeto é organizado em três camadas: pipeline (carrega dados, formata ontologia, monta prompt, executa inferência), avaliação (espelha o avaliador do benchmark, adiciona métricas de erro de formato e métricas estendidas), e scripts (orquestram tarefas de longa duração: indução C2, avaliação em lote, cálculo de pares C5). A execução em GPU acontece exclusivamente no Kaggle via lancador.ipynb. Localmente, toda a lógica de negócio pode ser testada sem GPU usando ProvedorMock.

Início›Pipeline›dados.py

dados.py — Carregamento do Benchmark

📂

src/t2kg/pipeline/dados.py

pipeline src/t2kg/pipeline/dados.py

Responsável por toda a leitura de dados do benchmark Text2KGBench. Conhece a estrutura exata de diretórios de TekGen e DBpedia/WebNLG, incluindo formatos distintos de treino (TekGen: uma tripla por linha; DBpedia: uma frase por linha com lista de triplas). Extrai automaticamente o par de exemplo dos prompts originais para uso em C1_oneshot_original.

FunçãoAssinaturaDescrição
carregar_frases (bench_dir, dataset, split, ontologia_id) → List[Dict] Carrega todas as frases de teste de uma ontologia. Cada dict contém: id, sent, gt_triples, exemplo_sent, exemplo_saida, prompt_original. Cruza ground-truth com prompts originais para extrair o par de exemplo.
carregar_frases_treino (bench_dir, dataset, ontologia_id) → List[Dict] Carrega frases de TREINO para indução C2. Lê diretamente de train/*.jsonl sem passar por _caminhos_gt(). Necessário para evitar o Bug 2 (D-17): split="train" retornava silenciosamente o GT de teste.
carregar_frequencias_treino (bench_dir, dataset, ontologia_id, k=3) → List[str] Retorna os k rótulos de relação mais frequentes no treino. Usado exclusivamente por C3 para evitar vazamento de informação do GT de teste (D-06).
Entrada

Arquivos JSONL do Text2KGBench:
data/wikidata_tekgen/ground_truth/ont_{onto}_ground_truth.jsonl
data/wikidata_tekgen/baselines/prompts/ont_{onto}_prompts.jsonl
data/wikidata_tekgen/train/ont_{onto}_train.jsonl

Saída

[{
  "id": "ont_1_movie_test_1",
  "sent": "Bleach... directed by Nolan",
  "gt_triples": [{sub, rel, obj}],
  "exemplo_sent": "...",
  "exemplo_saida": "director(Film, Nolan)"
}]

Detalhe crítico: TekGen armazena uma tripla por linha no treino (campo rel_label); DBpedia armazena uma frase por linha com campo triples. A função carregar_frases_treino() agrupa linhas TekGen por sentença antes de retornar.
Exemplo de uso
from t2kg.pipeline.dados import carregar_frases, carregar_frequencias_treino

frases = carregar_frases(BENCH, "tekgen", "test", "1_movie")
# frases[0] = {"id": "ont_1_movie_test_1", "sent": "Bleach...", "gt_triples": [...], ...}

top3 = carregar_frequencias_treino(BENCH, "tekgen", "1_movie", k=3)
# top3 = ["director", "screenwriter", "genre"]  (do treino, nunca do GT de teste)

ontologias.py — Carregamento e Formatação

🗂️

src/t2kg/pipeline/ontologias.py

pipeline src/t2kg/pipeline/ontologias.py

Carrega ontologias de referência (do benchmark) e induzidas (C2), e formata o bloco de contexto correspondente para cada condição experimental. A formatação varia por condição: C1 mostra conceitos + relações com assinaturas tipadas; C2 mostra apenas rótulos sem tipos; C3 mostra top-k relações com domínio/range; C5* usa a ontologia parceira no mesmo formato de C1.

FunçãoAssinaturaDescrição
carregar_ontologia (bench_dir, dataset, ontologia_id) → Dict Lê o arquivo JSON da ontologia de referência. Conhece os caminhos distintos de TekGen e DBpedia.
carregar_ontologia_induzida (dataset, ontologia_id) → Dict Carrega configs/c2/{dataset}_{onto}_induced.json. Lança FileNotFoundError com mensagem de remediação se o arquivo não existir. _REPO_DIR é patchável via monkeypatch para testes.
formatar_contexto (ontologia, condicao, top_k_rels=None, ontologia_parceira=None) → Optional[str] Função central. Retorna o bloco de contexto para cada condição. None para C0. Para C2: usa ontologia_parceira (a induzida). Para C5*: usa parceira se fornecida, senão usa alvo. Lança ValueError para condições desconhecidas.
Saída de formatar_contexto por condição
# C0 → None

# C1 / C1_oneshot_original / C5* (mesmo formato)
"Ontology Concepts: film, human, genre,\n"
"Ontology Relations: director(film,human), screenwriter(film,human), genre(film,genre)"

# C2 (ontologia induzida, sem tipos — D-25)
"Ontology Relations: released_in, directed_by, genre, is_a"

# C3 (top-3 treino com domínio/range)
"Relations: director(film,human), screenwriter(film,human), genre(film,genre)"
D-25: C2 usa o rótulo "Ontology Relations:" (igual a C1) mas sem conceitos nem assinaturas. Isso cria uma assimetria estrutural no avg_fmt_error — C2 não fornece nomes de classe que o modelo possa copiar como entidade.

prompts.py — Montagem dos Prompts

💬

src/t2kg/pipeline/prompts.py

pipeline src/t2kg/pipeline/prompts.py

Monta o prompt completo como string para cada condição experimental. Cada condição tem um ramo if explícito — condições desconhecidas levantam ValueError (nunca silenciosas). Compartilha a mesma instrução (inst_c1) entre C1 e C2, garantindo que os prompts sejam byte-a-byte idênticos dado o mesmo contexto_ontologia.

FunçãoAssinaturaDescrição
montar_prompt (sentenca, condicao, contexto_ontologia=None, exemplo_sent=None, exemplo_saida=None, instrucao_formato=None) → str Função única de montagem. instrucao_formato permite sobrescrever _INSTRUCAO_FORMATO para o mini-teste D-19. Ramos explícitos para: C0, C1+C2 (compartilhado), C3, C5+C5_vizinho+C5_incongruente, C1_oneshot_original. ValueError ao final para qualquer condição não reconhecida.
Exemplo — Prompt C1 (zero-shot, ontologia de referência)
prompt = montar_prompt(
    sentenca="Bleach: Hell Verse is a 2010 film directed by Noriyuki Abe.",
    condicao="C1",
    contexto_ontologia="Ontology Concepts: film, human,\nOntology Relations: director(film,human), genre(film,genre)"
)
# Resultado:
# "Given the following ontology and sentence, please extract the triples from the
#  sentence according to the relations in the ontology. Output the triples, one per
#  line, in this exact format: relation_name(, ).
#  No other text. Use as subject and object the exact entity names as written in the
#  sentence, never the ontology class names.
#
#  CONTEXT:
#  Ontology Concepts: film, human,
#  Ontology Relations: director(film,human), genre(film,genre)
#
#  Test Sentence: Bleach: Hell Verse is a 2010 film directed by Noriyuki Abe.
#  Test Output: "
Constantes de instrução
# D-20: Variante D — vencedora do mini-teste
_INSTRUCAO_FORMATO = (
    "Output the triples, one per line, in this exact format: "
    "relation_name(, "
    "). No other text."
)

# Usado apenas por C1_oneshot_original (fidelidade ao benchmark)
_INSTRUCAO_COM_ONT_BENCH = (
    "Given the following ontology and sentences, please extract the triples "
    "from the sentence according to the relations in the ontology. "
    "In the output, only include the triples in the given output format."
)
Invariante C1 == C2: quando o mesmo contexto_ontologia é passado para C1 e C2, os prompts são byte-a-byte idênticos. A diferença real está no conteúdo do contexto gerado por formatar_contexto(), não na estrutura do prompt.

executar.py — Execução com Checkpoint

▶️

src/t2kg/pipeline/executar.py

pipeline src/t2kg/pipeline/executar.py

Orquestra a extração de triplas para um par (ontologia, condição). Implementa checkpoint por ID: lê IDs já escritos no JSONL de saída e pula essas frases, permitindo retomada após falhas no Kaggle. Suporta execução paralela via ThreadPoolExecutor mas fixa workers=1 em todos os manifestos por reprodutibilidade (D-23).

FunçãoDescrição
executar Função principal. Carrega frases, ontologia, contexto. Pula IDs já processados (checkpoint). Para C2: carrega ontologia induzida. Para C3: carrega frequências de treino. Para C5*: carrega ontologia parceira. Escreve JSONL linha a linha.
_ids_ja_processados Lê IDs já escritos no JSONL de saída. Retorna set vazio se arquivo não existe. Tolerante a linhas corrompidas.
_registrar Append-only: escreve uma linha JSON no arquivo de saída. Cria diretórios se necessário.
Parâmetros chave de executar()

bench_dir: raiz do Text2KGBench
dataset: "tekgen" | "webnlg"
condicao: C0..C1_oneshot_original
frases_max: limita total (inclui checkpoint)
frases_seed: embaralha antes de frases_max
workers: 1 = sequencial (padrão D-23)
instrucao_formato: sobrescreve D-20 (mini-teste)

JSONL de saída (linha por frase)

{
 "id": "ont_1_movie_test_1",
 "sent": "Bleach... by Nolan",
 "prompt": "Given the following...",
 "response": "director(Bleach, Nolan)",
 "triples": [["Bleach", "director", "Nolan"]]
}

Lógica de checkpoint
ja_prontos = _ids_ja_processados(saida)   # IDs já no arquivo de saída
pendentes = []
for frase in frases:
    if frases_max is not None and (len(ja_prontos) + len(pendentes)) >= frases_max:
        break
    if frase["id"] not in ja_prontos:
        pendentes.append(frase)
# → pendentes conterá apenas as frases ainda não processadas

original.py — Avaliador Espelho

📊

src/t2kg/avaliacao/original.py

avaliação src/t2kg/avaliacao/original.py

Espelho fiel do avaliador original run_eval.py do Text2KGBench (Apache 2.0). Reproduz exatamente as métricas publicadas: P/R/F1, conformidade ontológica, alucinação de sujeito/objeto/relação. Adiciona três métricas: avg_fmt_error (D-07), avg_parse_error (D-18), e suporte a modo_amostra (D-04).

FunçãoDescrição
avaliar Função principal. Recebe config com onto_list (lista de {sys, gt, onto, output}) e avg_out_file. Escreve resultados por ontologia e média global em JSONLs.
calcular_precisao_recall_f1 P = corretas/preditas; R = corretas/gabarito; F1 = média harmônica. Aceita sets de triplas normalizadas.
normalizar_tripla Remove espaços e underscores, converte para minúsculas, concatena sub+rel+obj. Espelho exato do original para garantir comparabilidade.
calcular_alucinacao_sujeito_objeto Verifica se sujeito/objeto aparece como substring de (frase + labels dos conceitos). Concatenação SEM espaço entre frase e conceitos — espelho exato que reproduz o comportamento do original (incluindo o edge case que causa divergência com 2 frases no Windows).
calcular_taxa_erro_formato Detecta sujeitos/objetos que são exatamente o label de uma classe, têm o label como prefixo com ":", ou como prefixo com aspas. Contagem por tripla, não por entidade.
Regra crítica de espelhamento: P/R/F1 calculados SÓ sobre triplas cujo predicado aparece no gabarito daquela frase — não sobre todas as triplas extraídas. Saída vazia → P=R=F1=0, conformidade=1, alucinações=0. Médias por ontologia dividem pelo total de frases do gabarito (não pelo número avaliado), exceto com modo_amostra=True.

extended.py — Métricas Estendidas

📈

src/t2kg/avaliacao/extended.py

avaliação src/t2kg/avaliacao/extended.py

Métricas além do avaliador original. Inclui projeção de relações livres (C0) para a ontologia de referência via embedding (medida necessária para H1), redundância semântica (hipótese H1 principal), e normalização de rótulos antes do embedding (D-22).

FunçãoDescrição
_normalizar_rotulo Normalização antes de embedding (D-22): remove prefixos has_/is_ e sufixos _by/_of/_in/_to/_for. Faz com que directed_by, has_director, director_of sejam mais similares após encoding.
redundancia_semantica Para uma lista de rótulos de relação, computa a fração de rótulos que caem em grupos com cosine ≥ threshold. Mede H1: C0 deve ter maior redundância (vocabulário livre, não constrangido por ontologia).
avaliar_frase_estendida P/R/F1 sem filtro de ontologia + projeção de relações livres. Recebe sys_triplas e gt_triplas; projeta relações do sistema para o vocabulário da ontologia via embedding e recomputa P/R/F1.

parser.py — Parsing de Respostas LLM

🔍

src/t2kg/parser.py

pipeline src/t2kg/parser.py

Converte texto livre gerado pelo LLM em lista de triplas [[sub, rel, obj], ...]. Lida com prefácio antes das triplas, bullets numéricos, parênteses externos, vírgula final, e objetos com parênteses aninhados (depth-aware desde D-19).

FunçãoDescrição
parsear_resposta Função pública. Aceita texto do LLM. Detecta padrão rel(sub, obj) em cada linha. Retorna lista de triplas (pode ser vazia). Remove marcadores <> adicionados pela instrução Variante D.
_dividir_multiplas Implementação depth-aware (D-19): percorre caractere a caractere rastreando profundidade de parênteses. Divide apenas em vírgulas com profundidade == 0. Resolve is_a_song_by(Pavement, Summer Babe (Winter Version)) corretamente.
Exemplos de parsing
parsear_resposta("director(Bleach: Hell Verse, Noriyuki Abe)")
# → [["Bleach: Hell Verse", "director", "Noriyuki Abe"]]

parsear_resposta("is_a_song_by(Pavement, Summer Babe (Winter Version))")
# → [["Pavement", "is_a_song_by", "Summer Babe (Winter Version)"]]  # depth-aware D-19

parsear_resposta("director(, )")
# → [["Bleach: Hell Verse", "director", "Noriyuki Abe"]]  # remove <> de Variante D

parsear_resposta("Based on the ontology...\ndirector(Film, Nolan)")
# → [["Film", "director", "Nolan"]]  # ignora prefácio

induzir_c2.py — Indução da Ontologia C2

🧬

scripts/induzir_c2.py

script scripts/induzir_c2.py

Implementa o protocolo D-16 de indução da ontologia C2. Extrai triplas livres de frases de treino em modo C0, agrupa rótulos por similaridade de embedding (all-MiniLM-L6-v2), filtra por freq_min frases distintas (D-21), e salva a ontologia induzida com metadata.run_id para o guard check.

FunçãoDescrição
sortear_frases_treino Sorteia N frases de treino com seed fixa. Usa carregar_frases_treino() (nunca carregar_frases(split="train") — Bug 2 D-17).
extrair_triplas_com_respostas Extrai triplas livres de cada frase via montar_prompt(sentenca=f["sent"], condicao="C0"). Retorna tupla (triplas_por_frase, registros_raw) para salvar o JSONL bruto.
agrupar_relacoes Clustering greedy single-link por cosine similarity. Com normalizar=True (D-22) e definicoes={} (D-24), o embedding usa "rótulo_normalizado: definição". Retorna lista de dicts com label (mais frequente do grupo), frequência e membros.
contar_frases_por_grupo Adiciona n_frases a cada grupo: número de frases distintas com ≥1 tripla do grupo. freq_min filtra por este valor (não por contagem de triplas — corrigido em D-21).
construir_ontologia_induzida Constrói o dict da ontologia induzida: concepts: [] (nenhum — sem domain/range), relations: [{label, frequencia, membros}].
Exemplo de saída — configs/c2/tekgen_1_movie_induced.json
{
  "metadata": {
    "run_id": "20261110T143022Z",
    "dataset": "tekgen",
    "onto_id": "1_movie",
    "threshold_agrupamento": 0.70,
    "freq_min_frases": 3,
    "use_definicoes": true
  },
  "concepts": [],
  "relations": [
    {"label": "released_in", "frequencia": 9, "membros": ["released_in", "has_release_year", "released"]},
    {"label": "directed_by",  "frequencia": 6, "membros": ["directed_by", "directed"]},
    {"label": "genre",        "frequencia": 5, "membros": ["genre"]},
    {"label": "director",     "frequencia": 5, "membros": ["director_of", "has_director"]}
  ]
}
run_id e guard check: o campo metadata.run_id é gerado no Cell 9 do lancador como datetime.now(utc).strftime('%Y%m%dT%H%M%SZ') e passado via --run_id. O Cell 10 compara esse valor antes de iniciar qualquer experimento C2. Ontologia gerada em sessão anterior tem run_id diferente e bloqueia a execução com RuntimeError.

avaliar_resultados.py — Avaliação em Lote

📉

scripts/avaliar_resultados.py

script scripts/avaliar_resultados.py

Script de entrada para avaliação em lote. Lê um manifesto JSON, agrupa experimentos por (dataset, condição), detecta automaticamente modo_amostra comparando o número de linhas do sistema com o total do GT, e chama avaliar() de original.py para cada grupo. Com --extended, adiciona métricas de projeção e redundância.

Entrada

Manifesto JSON com lista de experimentos + arquivos JSONL de saída gerados pelo pipeline

Saída

├── tekgen_C0_avg.jsonl
├── tekgen_C1_avg.jsonl
└── tabela_piloto_v3.csv

Uso típico
python scripts/avaliar_resultados.py \
    --manifesto configs/pipeline/manifesto_piloto_v3.json \
    --bench_dir ../Text2KGBench \
    --avaliacao_dir resultados/avaliacao_piloto_v3 \
    --csv resultados/avaliacao_piloto_v3/tabela_piloto_v3.csv \
    --extended
